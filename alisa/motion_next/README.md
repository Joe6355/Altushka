# Алиса — продолжение анимаций

Размер каждого кадра — **36×86 пикселей**. Это следующий этап после `../walk_redo`: две передние диагонали, idle, начало и остановка шага, смена стороны и исходный танец. Полный набор из восьми направлений пока не готов.

## Файлы

- `Alisa_motion_next.mp4` — цельная сцена на игровом фоне, 21,2 секунды, 1280×960, 50 кадров/с. Исходный холст сцены 320×240 увеличен в четыре раза без сглаживания.
- `Alisa_start_stop.gif` — крупный просмотр старта, цикла шага и остановки.
- `Alisa_motion_next.aseprite` — 102 кадра, один слой, 10 тегов, индивидуальная длительность кадров.
- `Alisa_motion_next_atlas.png` — прозрачный атлас 360×946: 10 столбцов, ячейка 36×86, 8 пустых ячеек в последней строке.
- `Alisa_motion_next.json` — области кадров, длительности, теги и точки привязки.
- `Alisa_motion_next_timeline.json` — последовательность и координаты персонажа в ролике.
- `Alisa_scene_background.png` — фон сцены в исходном разрешении.
- `source/` — исходники сборки и экспорта.

## Анимации

| Тег | Кадры | Воспроизведение |
| --- | ---: | --- |
| idle_left | 0–7 | цикл, 2,4 с |
| start_left | 8–12 | один раз, 0,5 с |
| walk_left | 13–22 | цикл, 1 с |
| stop_left | 23–27 | один раз, 0,5 с |
| turn_left_right | 28–33 | один раз, 0,6 с |
| idle_right | 34–41 | цикл, 2,4 с |
| start_right | 42–46 | один раз, 0,5 с |
| walk_right | 47–56 | цикл, 1 с |
| stop_right | 57–61 | один раз, 0,5 с |
| dance_original | 62–101 | цикл, 4 с |

Левая ходьба покадрово совпадает с одобренным `walk_redo`; правая зеркальна ей. Начало и остановка используют три промежуточные позы между точными крайними кадрами. Idle содержит небольшой сдвиг ткани кофты на один пиксель; лицо, волосы, юбка и ноги в нём сохраняются.

Разворот использует цельные исходные позы 4, 5, 6 и их зеркальные варианты. Центральная смена стороны дискретная, как у обычного двухмерного спрайта.

Танец содержит все 40 исходных кадров с голубыми глазами и белой юбкой, без перерисовки. Начало цикла перенесено на исходный кадр 5, конец — на кадр 4 для совпадения со стойкой ожидания. В ролике танец повторяется дважды с 6,1 до 14,1 секунды.

## Подключение в игру

Обычная точка привязки — `(18, 85)` от верхнего левого угла ячейки. У танца точка привязки `(15, 85)`: эквивалентно сдвигу изображения на **+3 пикселя по X** относительно обычной точки. Это указано в `meta.frameTags[].pivot` и `drawOffset`; в ролике сдвиг уже учтён. Используй либо точку привязки, либо дополнительный сдвиг, чтобы не применить его дважды. Сам файл Aseprite хранит исходные кадры танца без сдвига и обрезки; привязку для игры нужно брать из JSON.

После последнего кадра `start_*` продолжай `walk_*` с локального кадра 1: контактный кадр 0 уже показан в старте. Завершай ходьбу на контакте 0 и затем показывай `stop_*` с локального кадра 1. Полные теги сохраняют обе крайние позы для отдельного просмотра. В ролике повтор крайних кадров убран.

Движение корня согласовано с кадрами: каждые 100 мс `(-3,8; +1)` пикселя для левой диагонали и `(+3,8; +1)` для правой. В ролике поза и корень обновляются одновременно.

## Сборка

Из корня репозитория при установленном Python с Pillow и NumPy:

```powershell
python alisa/motion_next/source/motion.py
python alisa/motion_next/source/motion.py --render
python alisa/motion_next/source/motion.py --verify-video
```

Первый запуск пересобирает PNG, JSON, Aseprite и GIF. `--render` дополнительно создаёт MP4 и проверяет его декодированием. Видеокодер использует FFmpeg DLL из установленного Blender 5.1; путь указан в `encode.py` и `refdecode.py`.

Проверки сборки сравнивают все пиксели Aseprite с атласом, одобренные кадры ходьбы с `walk_redo`, исходный танец с `recolor/blue_eyes`, а также крайние позы переходов. Проверка видео контролирует 1060 кадров, временные метки и расхождение декодированного изображения с рендером.
