# Алиса — вид со спины и задние диагонали

Три новых направления с тем же нативным кадром **36×86 пикселей**: прямо от камеры, от камеры вправо и от камеры влево. Для каждого есть idle, начало шага, десятикадровая ходьба и остановка. Руки остаются на бёдрах, как в одобренном боковом цикле. Волосы, кофта и белая юбка сохраняют его палитру и ориентиры пропорций.

## Просмотр

- `Alisa_back_scene.mp4` — непрерывная сцена13,7с на прежней площадке. Алиса идёт от камеры, останавливается, поворачивается и проходит обе задние диагонали. 1280×960,50кадров/с; исходная сцена320×240 увеличена вчетверо без сглаживания.
- `Alisa_back_walk.gif` — три цикла крупным планом. Слева направо: задняя правая диагональ, вид прямо со спины, задняя левая диагональ.
- `Alisa_back_transitions.gif` — idle → старт → полный цикл → остановка, одновременно для трёх направлений.
- `Alisa_back_idle.gif` — ожидание в трёх новых ракурсах.
- `Alisa_back_model.png` — одобренная боковая стойка рядом с новыми ракурсами для сравнения фигуры и одежды.

Развороты в сцене выполняются в стойке обычной сменой направления спрайта. Между задними диагоналями показана промежуточная стойка прямо со спины.

## Для Aseprite и игры

`Alisa_back.aseprite`: **72 кадра,12тегов,6слоёв**. Слои: задняя нога, таз, передняя нога, юбка, кофта, голова. `Alisa_back_atlas.png` — прозрачный атлас360×688: десять столбцов, восемь строк, ячейка36×86; последние восемь ячеек пустые. `Alisa_back.json` содержит области кадров, длительности, теги, привязки и смещение тени.

| Тег | Кадры | Длительность |
| --- | ---: | --- |
| idle_back | 0–3 | 2,4с, цикл |
| start_back | 4–8 | 0,5с, один раз |
| walk_back | 9–18 | 1с, цикл |
| stop_back | 19–23 | 0,5с, один раз |
| idle_back_right | 24–27 | 2,4с, цикл |
| start_back_right | 28–32 | 0,5с, один раз |
| walk_back_right | 33–42 | 1с, цикл |
| stop_back_right | 43–47 | 0,5с, один раз |
| idle_back_left | 48–51 | 2,4с, цикл |
| start_back_left | 52–56 | 0,5с, один раз |
| walk_back_left | 57–66 | 1с, цикл |
| stop_back_left | 67–71 | 0,5с, один раз |

После последнего кадра старта продолжай соответствующую ходьбу с локального кадра1: контактный кадр0 уже показан. Завершай ходьбу на контакте0, затем показывай остановку с локального кадра1. Полные теги содержат обе крайние позы для отдельного просмотра. Ролик уже учитывает это правило.

Привязка `(18,85)` для вида со спины и правой диагонали, `(17,85)` для зеркальной левой. В демонстрации каждые100мс корень смещается на `(0,-2)` пикселя для прямого движения от камеры и `(±3,8,-1)` для диагоналей. Поза и положение обновляются одновременно. Движение в глубину сокращено относительно горизонтального движения, как у слегка приподнятой камеры.

Крайние кадры старта точно совпадают со стойкой и контактом шага; остановка возвращает исходную стойку. Лицо не поворачивается к игроку: сзади глаз нет, в диагоналях виден только небольшой край щеки. Корпус опускается до2пикселей, перенос веса даёт боковой сдвиг до1пикселя; подол отклоняется до2пикселей относительно пояса, завиток — до1пикселя.

`Alisa_back_timeline.json` хранит последовательность клипов и координаты ролика. Фон находится в `Alisa_scene_background.png`. Одобренные файлы `side_walk`, `walk_redo` и `motion_next` в этой итерации не менялись.

## Исходники и сборка

Две опорные позы созданы встроенным `image_gen.imagegen` по одобренному референсу Алисы. Изображения переведены в сетку36×86 и ту же палитру20цветов, что у бокового ракурса. Десять силуэтов ног для каждого нового вида, тени, переносы стоп и движения слоёв заданы в `source/rear.py`; левый задний ракурс зеркален правому.

В `source/` сохранены исходные сгенерированные позы, их нативные основы, референс и полный набор промптов `imagegen_prompts.txt`. `prepare_native.py` воспроизводит перевод в нативную сетку, `rear.py` — сами слои и позы, `build.py` — экспорт и сцену.

Из корня проекта, Python с Pillow и NumPy:

```powershell
python alisa/back_walk/source/prepare_native.py
python alisa/back_walk/source/build.py
python alisa/back_walk/source/build.py --render
python alisa/back_walk/source/build.py --verify-video
```

Первый запуск нужен для пересоздания нативных основ из сохранённых референсов. Второй экспортирует PNG, JSON, Aseprite и GIF; `--render` дополнительно создаёт MP4. Для видеокодирования и декодирования используются FFmpeg DLL установленного Blender5.1.

Все72кадра Aseprite прочитаны обратно по слоям и побайтно сравнены с атласом. Проверены границы контуров до обрезки холстом, крайние позы переходов, устойчивость опорных стоп и зеркальное соответствие диагоналей. В ролике проверены685кадров, временные метки и декодированное изображение.
